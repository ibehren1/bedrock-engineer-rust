# MCP サーバー設定

Model Context Protocol (MCP) クライアント統合により、Bedrock Engineerは外部のMCPサーバーに接続し、強力な外部ツールを動的にロードして使用することができます。この統合により、AIアシスタントがMCPサーバーが提供するツールにアクセスして利用できるようになり、その能力が拡張されます。

## 設定形式

MCP サーバーの設定は、Claude Desktop互換の`claude_desktop_config.json`形式を使用します。設定はエージェントエディター（マイエージェントページ）の「MCPサーバー」タブで行います。サーバーはエージェントごとに設定します。

MCP サーバーは以下の2つの形式で設定できます：

### 1. コマンド形式（ローカルサーバー）

```json
{
  "mcpServers": {
    "サーバー名": {
      "command": "実行コマンド",
      "args": ["引数1", "引数2"],
      "env": {
        "環境変数名": "値"
      }
    }
  }
}
```

### 2. URL形式（リモートサーバー）

```json
{
  "mcpServers": {
    "サーバー名": {
      "url": "https://example.com/mcp-endpoint",
      "headers": {
        "Authorization": "Bearer <トークン>"
      }
    }
  }
}
```

`headers`は省略できます。アプリはStreamable HTTPトランスポートで接続し、失敗した場合は従来のSSEトランスポートに切り替えます。

macOSとLinuxでは、`npx`や`uvx`などで起動するコマンド形式のサーバーは、アプリをDockやデスクトップのランチャーから開いた場合でも、ログインシェルの`PATH`を参照します。

## 設定例

```json
{
  "mcpServers": {
    "fetch": {
      "command": "uvx",
      "args": ["mcp-server-fetch"]
    },
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "~/"],
      "env": {
        "NODE_ENV": "production"
      }
    },
    "DeepWiki": {
      "url": "https://mcp.deepwiki.com/sse"
    }
  }
}
```

## よく使用されるMCPサーバー

- **fetch**: Web上のコンテンツを取得するツール
- **filesystem**: ファイルシステム操作ツール
- **DeepWiki**: ナレッジベース検索ツール
- **git**: Git操作ツール
- **postgres**: PostgreSQLデータベース操作ツール

## ローカルナレッジベース用の組み込みサーバー

ローカルナレッジベース（エージェントエディター →「ナレッジベース」タブ）を持つエージェントには、`local-knowledgebase`サーバーが自動的に追加されます。このサーバーはアプリ内で動作するため、インストールや設定は不要です。エージェントの`mcpServers` JSONには含まれず、エージェントの実行時に追加され、最後のナレッジベースを削除すると外れます。ツールは`searchKnowledgeBase`、`listKnowledgeBases`、`listKnowledgeBaseSources`です。

「MCPサーバー」タブでは、エージェント自身のサーバーの上に**組み込み**として読み取り専用で表示され、**接続テスト**ボタンがあります。「ツール」タブには、他のMCPツールと一緒にそのツールが表示されます。ナレッジベース自体は「ナレッジベース」タブと**設定 → ナレッジベース**で管理します。

## MCPサーバーを探す

「MCPサーバー」タブには、[公式 MCP レジストリ](https://registry.modelcontextprotocol.io)を使う**MCPサーバーを探す**パネルがあります：

- **検索**はレジストリを直接検索します（`/v0/servers?search=…&version=latest`）。
- **このエージェント向けに提案**は、エージェントの設定から検索キーワードをモデルに考えさせ、その検索を実行します。モデルが作るのは検索キーワードだけで、表示されるサーバー、バージョン、パッケージ識別子はすべてレジストリから取得したものです。
- **MCP レジストリ**と**MCP Market**は、それぞれのディレクトリをブラウザーで開きます。

提案が参照する情報（役に立つ順）：

| 情報源                          | 重要な理由                                                               |
| ------------------------------- | ------------------------------------------------------------------------ |
| システムプロンプト              | エージェントが扱うシステム、製品、データソースなど具体的な内容が書かれる |
| シナリオ                        | 具体的なタスクで、実際のツール名が含まれることが多い                     |
| 許可するシェルコマンド          | `kubectl`や`gh`のパターンはシステムを直接示す                            |
| 追加の指示                      | 生成されたプロンプトに追加される補足                                     |
| 説明、カテゴリ                  | 大まかな手がかり。プロンプトが薄い場合に使う                             |
| 有効なツール、既存のMCPサーバー | 提案から除外（すでに持っているものは提案しない）                         |

各キーワードは設定内の語句に基づいている必要があり、UIではキーワードの横にその語句が表示されます。一般的な語（`automation`、`devops`、`deployment`、`monitoring`など）はディレクトリで有用な結果にならないため除外されます。設定からシステムを特定できない場合、パネルは推測せずにその旨を表示します。システムプロンプトを追記するか、レジストリを直接検索してください。

各結果には、レジストリ上の名前、バージョン、実行方法、必要な環境変数が表示されます。「設定を読み込む」を押すと、JSONエディターに次の内容が入ります：

- npmパッケージは`npx -y <識別子>@<バージョン>`
- Pythonパッケージは`uvx <識別子>`
- ホスト型サーバーはリモートの`url`
- サーバーが必要とする環境変数は、値が空の`env`キー

パッケージ情報なしで公開されているサーバーには、設定の代わりに注意書きが表示されます。実行方法はソースリポジトリを確認してください。「サーバーを追加」を押すまで何も追加・接続されないため、必ず先にコマンドを確認できます。

[MCP Market](https://mcpmarket.com)はカテゴリ別に閲覧するためのリンクとして表示されますが、アプリはその内容を読み込みません。APIが公開されておらず、`robots.txt`がすべてのエージェントに`/api/`を禁止しており、自動リクエストにはVercelのボットチャレンジが返されるためです。

## 設定手順

1. マイエージェントページからエージェントエディターを開く
2. 「MCPサーバー」タブを選択
3. 「新しいMCPサーバーを追加」ボタンをクリック
4. 上記のJSON形式で設定を入力
5. 「接続テスト」で接続をテスト
6. 設定を保存

## トラブルシューティング

**接続エラーが発生する場合：**

- コマンドパスが正しいか確認
- 必要な依存関係がインストールされているか確認
- 環境変数が正しく設定されているか確認

**設定エラーが発生する場合：**

- JSON形式が正しいか確認
- `mcpServers`オブジェクトが含まれているか確認
- サーバー名が重複していないか確認
